# News-RSS（My News Dashboard）

登録したキーワードで Google ニュースを検索し、主要ニュース（Yahoo・Google・NHK・読売）と
ブログ（はてな・note）と合わせて**1画面で読むためのニュースダッシュボード**です。
サーバー側は RSS を取りに行く関数が1本だけで、キーワードやお気に入りは全部ブラウザに保存します。
会員登録も DB もありません。

読者：このリポジトリを初めて開いた技術者（次に触るエージェント、将来の自分を含む）。

最終更新: 2026-09-16（画面のバージョン表記は v8.9、2026-07-22）

---

## 1. これは何か

ニュースアプリは「向こうが選んだ記事」を流してきます。このダッシュボードは逆で、
**自分が決めた語（例：地元の自治体名、関心のある政策、人名）で毎回検索し、新しい順に並べる**だけのものです。

- スマホでも PC でも同じ URL を開けば使える（レイアウトは幅で切り替わる）
- キーワードは「政治」「地元」のようにグループにまとめ、画面上のボタンで切り替える
- 同じ話題の記事が何本あるかを数えて「話題順」にも並べられる
- 気になる語には 🔔 を付けると、新着をブラウザ通知で知らせる

作者が最初に作った Web アプリで、2026-05-08 に始まり、その後 Cursor 上のエージェントとの
PR で機能を足していきました（お気に入り・期間絞り込み・キーワードグループ・自動更新など）。

## 2. できること（タブごと）

| タブ | 取得元 | できること |
|---|---|---|
| 🔍 ニュース | Google ニュース RSS 検索（キーワードごとに1リクエスト） | 登録キーワードで検索。キーワード順・話題順・新しい順、期間（今日／24時間／3日）、キーワード別の絞り込み |
| 🌍 主要 | Yahoo!（トピックス・国内）、Google ニュース トップ、NHK（主要・社会・政治）、読売（政治・社会）、Google「天気 気象」検索 | 見出しの語からカテゴリ（政治／経済／社会／天気／国際／芸能／スポーツ／その他）を自動判定し、カテゴリで絞り込む |
| 📝 ブログ | はてなブックマーク タグ検索、note ハッシュタグ | 語を入れて検索。未入力なら「注目」「ニュース」 |
| ★ お気に入り | （ブラウザ内） | ★ を付けた記事を新しい順に |

共通の機能：

- **キーワードグループ**：キーワードの一覧に名前を付けて保存。表画面のボタンで切り替え、追加・削除は表示中のグループに反映される。取得範囲は「表示中のグループ」か「全グループ」を選べる
- **除外（NG）ワード**：全タブ共通。見出し・出典に含まれる記事を落とす
- **話題順**：見出しのバイグラム一致（類似度 0.35 超）で同じ話題の記事をまとめ、本数を「関連 N 件」として表示。多い順に並べる（`applyTopicScores`）
- **既読**：開いた記事は薄く表示（リンクをブラウザに保存）
- **新着通知**：キーワード右の 🔔 をオンにし「通知を許可」を押すと、その語の新着記事を Notification API で通知。既に通知したリンクは覚えておく
- **自動更新**：1〜30分間隔で表示中のタブを再取得
- **件数**：10〜100件

## 3. 使い方

### 構成の前提

```
index.html   画面と全ロジック（1ファイル、約1,700行）
api/rss.js   RSS を取りに行くサーバー関数。/api/rss?keyword=...&type=news|major|social&exclude=...&count=...
```

画面は `fetch('/api/rss?...')` で関数を呼びます。関数は `module.exports = async (req, res)` の形で、
`res.status(200).json(...)` を返す **Vercel の Serverless Functions と同じ形式**です。
履歴上、2026-05-08〜13 は Netlify Functions（`netlify/functions/rss.js`）で動かし、
2026-05-13 に `api/` 形式へ移しています。**配備先の設定ファイル（`vercel.json` など）はリポジトリに無く、
本番 URL も書かれていません。** 配備先は Vercel と推定していますが未確認です。

### ローカルで動かす

```
npm install                 # axios だけ
npx vercel dev              # Vercel CLI があれば。/ と /api/rss の両方が動く
```

Vercel CLI が無い場合は、`api/rss.js` を Express などで `/api/rss` に載せ、`index.html` を同じオリジンから配信すれば動きます
（画面は相対パス `/api/rss` を呼ぶため、別オリジンにすると CORS で失敗します）。

### `api/rss.js` の動き

1. `type` に応じて取得先を並べ、**全部同時に**取りに行く（1つ 3.8 秒でタイムアウト、失敗したフィードは空扱い）
2. 各フィードから最大 30 件。文字コード（Shift_JIS／EUC-JP など）を見てデコードし、HTML エンティティを戻す
3. Google ニュースは「見出し - 媒体名」の形なので、媒体名を出典として切り出す
4. `exclude` の語と**組み込みの除外語**（`api/rss.js` 内。作者の事情による固定の除外）で見出し・出典を落とす
5. リンクで重複を除き、公開日時の新しい順に並べ、`count`（上限 100）件を返す
6. `Cache-Control: public, max-age=60`（同じ条件の再取得は 60 秒間キャッシュされ得る）

## 4. データの扱い

**サーバーには何も保存しません。** 利用者の設定はすべてブラウザの `localStorage` に入ります。

| キー | 中身 |
|---|---|
| `myKeywords`／`myKeywordGroups` | キーワードの一覧と、名前付きグループ |
| `myNgWords` | 除外ワード |
| `myFavorites` | お気に入り記事（見出し・リンク・日時） |
| `myVisitedLinks` | 既読リンク |
| `myNotifyKeywords`／`myKnownNotifyLinks`／`mySeededNotifyKeywords` | 通知対象の語と、通知済みリンク |
| `myFetchCount`／`myFetchScope`／`myPeriodFilter`／`myAutoRefreshMin` | 件数・取得範囲・期間・自動更新の設定 |

このため、**別の端末やブラウザには引き継がれません**（スマホと PC で別々に登録が要る）。
ブラウザのサイトデータを消すと全部消えます。書き出し・読み込みの機能はありません。

## 5. 構成（読む順番）

```
index.html          〜235 行が CSS、〜430 行が HTML、以降が JS
                    handleFetch()（取得と articleCacheByKeyword への保持）
                    → renderTable()（絞り込み・並び替え・描画）
                    applyTopicScores()／calcSimilarity()  話題順
                    autoCategorize()                      主要タブのカテゴリ判定（正規表現の加点）
                    キーワードグループ・通知・自動更新は localStorage の読み書きとセット
api/rss.js          fetchAndParse()（1フィード）→ 結合・除外・重複除去・並び替え
package.json        依存は axios のみ
AGENTS.md           Hub 経由で扱うときの同期規則
```

直すときの目安：取得先やパースの問題は `api/rss.js`、見え方・絞り込み・保存の問題は `index.html`。
`index.html` は分割されていないので、関数名で検索して該当箇所だけ読むのが早いです。

## 6. テストと確認方法

自動テストはありません。確認は手で行います。

- `api/rss.js`：`/api/rss?type=major&count=5` を直接開き、JSON が返り、`published` が新しい順で、`source` が入っていることを見る。
  `?type=news&keyword=<語>` でも同様
- `index.html`：3タブとも取得できること、キーワードの追加→グループ保存→切替→再読み込み後も残ること、
  🔔 と「通知を許可」で通知が出ること（HTTPS か localhost でないと Notification API は動かない）
- スマホ幅（600px 以下）では「絞り込み」ボタンからシートが開く。PC 幅とは別の要素（`*-mobile`）なので両方見る

## 8. 現状と制限

- **区分：開発継続。** 日常利用はしているが、2026-07-22 の v8.9 以降は機能追加なし
- フィードの取得に失敗しても空として返すため、画面からは「記事が無い」のか「取れなかった」のか区別できない。
  全フィードが失敗したときだけ「通信が混み合っています」と出る
- 取得先の RSS（Google ニュース・Yahoo・NHK・読売・はてな・note）は先方の仕様変更で止まり得る。監視は無い
- 主要タブのカテゴリ判定は見出しの語への加点で、誤判定はある（政治 > 社会 > 天気 > … の優先順で決める）
- 話題順のまとめ方は見出しの文字の重なりだけで、同じ話題でも言い回しが違うと分かれる
- 設定はブラウザごと。端末間の同期、書き出し、複数人での共有はできない
- `api/rss.js` に固定の除外語が埋め込まれている。汎用に配るならここを設定に出す必要がある
- 配備先・本番 URL がリポジトリに無い（§3）。次に触る人は先に確認する

## 9. 主な依存

Node.js（Serverless Functions）、axios。画面側はフレームワーク無しの素の HTML／CSS／JS。
