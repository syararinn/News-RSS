# NotebookLM生成プロンプト集

NotebookLM の Studio パネルで「スライド」または「インフォグラフィック（1枚の資料）」を
生成する際に、そのままカスタマイズ欄へ貼り付けて使えるプロンプト文例集。

前提として、このフォルダ内の Markdown ファイル（特に `07_AI活用事例レポート用サマリー.md` を核に、
`01`〜`06` を補足資料として）をすべてソースに追加済みであること。

## 0. 共通の前提条件（プロンプトに含めている要素）

以下の条件をすべてのプロンプトに反映している。

- **対象読者**：直属の上司（社内向け、少人数）
- **目的**：社内のAI活用事例として、生成AIでこのソフトを開発した取り組みを手短に共有する
- **トーン**：社内報告らしく簡潔。売り込み口調にしない
- **深さ**：機能の詳細説明・画面操作手順・実装の技術詳細には踏み込まず、
  「こんなソフトをAIを使って作った」という程度の概要にとどめる
- **必ず含める内容**：なぜ作ろうと思ったか（背景・課題）／どうやって作ったか
  （生成AI・AIコーディングエージェントに要件を伝える形で開発した、という進め方自体が
  AI活用のポイントであること）／出来上がったものの概要（軽く）／期待できる効果／今後の展望
- **含めない内容**：細かい機能一覧、実装の技術詳細、対外的な強い訴求表現、実在の担当者名

## 1. まず構成案（アウトライン）だけを確認するプロンプト

スライド・インフォグラフィックいずれの場合も、**いきなり本生成せず**、
まず次のプロンプトで構成案だけを出してもらい、内容を確認してから本生成に進むこと。

```
あなたはこの後、社内向けのスライド資料（または1枚のインフォグラフィック）を作成します。
まだ本生成はせず、先に「構成案（アウトライン）」だけを箇条書きで提示してください。

【資料の目的】
社内の「AI活用事例」報告として、生成AI（AIコーディングエージェント）を使って
ソフトウェアを開発したという取り組みを、直属の上司に手短に共有するための資料です。
ソフトの機能を詳しく売り込むことが目的ではありません。

【対象読者】
直属の上司（社内向け、少人数）。技術的な前提知識は多くを求めない。

【トーン】
社内報告らしく簡潔に。売り込み・宣伝のような口調は避ける。

【構成案に含めてほしい要素】
1. なぜ作ろうと思ったか（背景・課題）
2. どうやって作ったか（生成AI・AIコーディングエージェントに要件を伝える形で
   開発した、という進め方自体がAI活用のポイントであることを明記する）
3. 出来上がったものの概要（機能を詳しく説明せず、軽く触れる程度）
4. 期待できる効果
5. 今後の展望

【含めないでほしい要素】
- 細かい機能一覧や画面操作手順
- 実装の技術的な詳細（プログラミング言語、アルゴリズム、データ構造など）
- 対外的な強い訴求表現やキャッチコピー的な誇張
- 実在の担当者名（「担当者」など一般化した表現にする）

各項目について、スライド1枚（またはインフォグラフィックの1ブロック）に
何を載せるかが分かる程度の粒度で、簡潔に構成案を出してください。
まだデザインや本文の細かい文章は不要です。
```

このアウトラインの内容・粒度・トーンを確認し、問題なければ以下の本生成プロンプトに進む。
過不足があれば「◯番の項目をもっと簡潔に」のように追加で指示し、アウトラインを調整してから
本生成すること。

## 2. スライド生成用プロンプト（6枚程度）

```
先ほど確認した構成案に沿って、社内向けのスライド資料を6枚程度で生成してください。

【目的】
社内の「AI活用事例」報告として、生成AI（AIコーディングエージェント）を使って
このソフトウェアを開発した、という取り組み自体を直属の上司に手短に共有すること。
ソフトの機能を売り込むためのプレゼンではありません。

【対象読者】
直属の上司（社内向け、少人数）。

【トーン】
社内報告らしく簡潔に。プレゼン的な煽り文句や、対外的な強い訴求表現は使わない。
落ち着いた事実ベースの言い回しにする。

【枚数】
6枚程度（表紙を含めても含めなくても良いが、全体でこの枚数感に収める）。

【各スライドに求める内容の目安】
1. タイトル／位置づけ（何についての報告か、一言で）
2. なぜ作ろうと思ったか（背景・課題）
3. どうやって作ったか（生成AI・AIコーディングエージェントに要件を伝える形で
   開発したこと。開発の「進め方」自体が今回のAI活用のポイントであることを明記する）
4. 出来上がったものの概要（機能の詳細には踏み込まず、軽く触れる程度）
5. 期待できる効果
6. 今後の展望・まとめ

【深さについての指示】
- 細かい機能一覧や画面操作手順には踏み込まない。
- 実装の技術的な詳細（使用技術、アルゴリズム、データ構造など）には踏み込まない。
- 「こんなソフトをAIを使って作った」という程度の概要にとどめる。

【表現についての指示】
- 対外的な強い訴求表現（キャッチコピー的な誇張表現）は使わない。
- 実在の担当者名は使わず、「担当者」のように一般化した表現にする。
- 数字を使う場合は、ソースに記載のある事実ベースの数字のみを使う。

以上の条件で、社内向けの簡潔なスライドを生成してください。
```

## 3. 1枚インフォグラフィック生成用プロンプト

```
社内向けの「AI活用事例」報告として、1枚のインフォグラフィックを生成してください。

【目的】
生成AI（AIコーディングエージェント）を使ってこのソフトウェアを開発した、
という取り組み自体を、直属の上司に一目で伝えること。
ソフトの機能を売り込むための資料ではありません。

【対象読者】
直属の上司（社内向け、少人数）。

【トーン】
社内報告らしく簡潔に。対外的な強い訴求表現やキャッチコピー的な誇張は使わない。

【1枚に含めてほしい要素（レイアウトの目安）】
- 上部：何についての報告か（タイトル・一言の位置づけ）
- 背景・課題：なぜ作ろうと思ったか
- 進め方：生成AI・AIコーディングエージェントに要件を伝える形で開発した、
  という進め方自体が今回のAI活用のポイントであることが伝わる説明
- 出来上がったものの概要：機能の詳細ではなく、軽く触れる程度の説明
- 数字で見る特徴：ソースにある事実ベースの数字を2〜4個程度ピックアップ
- 期待できる効果・今後の展望：簡潔に1〜2行程度
- 締めのメッセージ：1行程度

【深さについての指示】
- 細かい機能一覧、画面操作手順、実装の技術的詳細には踏み込まない。
- 「こんなソフトをAIを使って作った」という程度の概要にとどめる。

【表現についての指示】
- 実在の担当者名は使わず、「担当者」のように一般化した表現にする。
- 対外的な強い訴求表現は使わない。

以上の条件で、社内報告用の1枚インフォグラフィックを生成してください。
```

## 4. 補足：生成後にトーン調整したいときの追加指示例

生成結果が少し宣伝寄り・技術寄りになってしまった場合に使える追加プロンプト例。

```
生成された内容が少し売り込み口調（または技術的すぎる説明）になっています。
社内向けの淡々とした報告トーンになるように、以下の観点で調整してください。

- 「業界初」「圧倒的」「劇的に」のような強い訴求表現があれば、事実ベースの控えめな表現に変える
- 実装の技術用語（使用技術名、アルゴリズム名、データ構造名など）が出てきていれば取り除く
- 機能の説明が細かすぎる場合は、1〜2行程度の概要レベルに要約し直す
- 実在の担当者名が含まれていれば「担当者」に置き換える
```
